Write a Cytron tutorial, from login to publish.

A tutorial page shows how a product works before a customer orders, and it is where customers and customer support staff come back to when something goes wrong. Write every step for a complete beginner who knows nothing about digital making. This page is the only reference you need.

01

Get access and create the post

Every tutorial is written and published in WebAdmin. Set up the post before you write a word.

  1. Ask your supervisor to set up your WebAdmin username. Every supervisor can do this. Choose a short username, not your full name as it appears on your IC.
  2. Open cytron.io/admin and log in with your username. The first time, use Forgot Password to set your password.
  3. Expand the Tutorial tab on the left and select Tutorials, then click + to create a new post.
  4. In the Data tab, set the SEO URL first. It also names the folder your images upload into.
  5. Fill every field in the General, Data, Links and Image tabs (step 02).
  6. Write the body in the Description field, following the structure in step 03.
  7. Click Save every time you make a change.
02

Fill every WebAdmin field

Fill every field before writing the body. Every field below is MUST.

All SEO fields are compulsory. A tutorial with an empty or incomplete SEO field is not ready to publish.

Post Name
Short, clear tutorial title, 60 characters at most. Avoid numbers (such as version numbers) unless required. Don't repeat the title in the body.
e.g.ESP32 High Temperature Alert System
PitchMeta Tag Description
Meta description, not shown on the page. One complete sentence, 160 characters at most, unique to this tutorial:
Build a/an [project] using Maker ESP32 and [main part] to [outcome].
e.g.Build an IoT water tank monitor using a Maker ESP32 and an ultrasonic sensor to track water levels in real time from any browser. (129)
Description
The tutorial body. Follow step 03.
Post Tags
Keywords or phrases for the topic: ESP32, Maker ESP32, then the main modules, protocols and topic.
e.g.ESP32 · Maker ESP32 · IoT · Ultrasonic Sensor · WebServer · Arduino
Meta Tag Keywords
3 to 8 searchable keywords, comma-separated. Never paste the Pitch into it.
e.g.ESP32, Maker ESP32, DHT11, Temperature Alert, Buzzer
Meta Tag Title
The title shown in search results and browser tabs: the Post Name, optionally plus the key technology. 60 characters at most.
e.g.ESP32 Water Tank Monitoring with Web Dashboard
Context Menu
Target audience: choose one, Education or Industry.
SEO URL
The tutorial title in lowercase, hyphens for spaces, no special characters. Set it first: it also names the image folder.
e.g.esp32-digital-clock
Image Folder Name
Filled in by WebAdmin and locked. All images for this post upload into this folder. It does not follow later SEO URL changes, so get the SEO URL right before you first save.
e.g.esp32-digital-clock
Publish Date
The date it becomes visible to the public. Always set it to the actual publish date, not the date you wrote the tutorial.
Post Type
Tutorial, Project, Protip, News or Uncategorised.
e.g.Tutorial
Project Level
Beginner
A microcontroller with 1 or 2 sensors, or basic Raspberry Pi functions
Intermediate
2 or more sensors, or Raspberry Pi software projects
Advanced
AI projects, basic Industry
Expert
Complex AI, complex Industry
Status
Enabled (public), Disabled (hidden), or Enabled but hide in catalog (unlisted, reachable by its SEO URL).
Sort Order
Set it to 1, unless your supervisor makes a special request.
Author
Your name from the dropdown.
Categories
The categories that match the content.
e.g.Wireless & IoT > Maker ESP32
Store Name
Tick every store first. Then untick a store only if a Related Product is not available there (for example, untick TH if a product isn't sold in the TH store).
Parent
Only for a series: the main post (for example the series hub) that this part belongs to. Leave empty for a standalone tutorial.
Related Post

SEO rules that apply after publishing

    Never change the SEO URL after publishing. If you must, redirect the old URL to the new one, keeping /tutorial/ in the path.A redirect without /tutorial/ sends readers to a 404.
  • MUST

03

Write the tutorial

Write the body in the Description field. Write for complete beginners, in clear, simple language, with active voice and short sentences. MUST

3.1Required structure

Every tutorial uses these headings, in this order, worded exactly as shown. The page title is set in Post Name and never repeated in the body, so the body starts at H2. No H1 in the body, no empty headings.

  1. 01IntroductionH2MUST2 to 4 sentences: what the reader builds and why it matters for Education or Industry use. Open with the reader's problem. Optional hero image or 30 to 60 s video teaser after the paragraph.
  2. 02Disclaimer / Safety NotesH2IF APPLICABLEElectrical, battery or heat cautions, warranty notes, classroom supervision. See Safety notes.
  3. 03PrerequisitesH2MUSTLink the Getting Started guides or basics to finish first. Name the software, accounts, firmware or SDKs to install.
  4. 04ObjectivesH2MUSTOne paragraph only.
  5. 05List of ComponentsH2MUSTNumbered list, [Product name] x1, name linked, opens in a new window. See Components & links.
  6. 06System Diagram & WiringH2MUSTA block or circuit diagram (Canva, Fritzing) at its native aspect ratio, plus a pin-to-pin wiring table: [Board], [Module], Function. Add a Note: for mounting tips or other ways to connect.
  7. 07Software SetupH2MUSTIDE or toolchain version, library names with install steps, board and port selection. Screenshots encouraged.
  8. 07aInstall [Library name] LibraryH3IF A LIBRARYNumbered Library Manager steps, including the "Install All" dependency prompt.
  9. 08Sample CodeH2MUST"Upload the following sketch to your Maker ESP32:" then a public GitHub Gist embed.
  10. 08aKey Code ExplanationH3MUSTBrief explanation of the key blocks: one bullet per line, code: what it does.
  11. 09Testing & ValidationH2MUSTNumbered steps to run and verify. Put a short troubleshooting note inline where a step often fails.
  12. 09aExpected ResultsH3MUSTExpected outputs: Serial Monitor lines, LEDs, sounds, browser view.
  13. 10Demo / ResultsH2MUSTPhotos or a YouTube embed of the working project, and screenshots of dashboards or the Serial Monitor.
  14. 11Troubleshooting & Extra TipsH2MUST3 to 4 H3s, each a symptom as the reader sees it, with bullet fixes: power, baud rate, library conflicts, sensor orientation, calibration.
  15. 12Downloads & AssetsH2IF APPLICABLEZIP of diagrams or configs, repo links, datasets, example flows, STL or 3D files.
  16. 13Telegram community bannerno headingMUSTOne banner at the very end, linked to the matching community. See Telegram banner.

The Hardware Components block and Related Posts below the body come from the Related Product, Parent and Related Post fields in the Links tab, not from the body.

Copy-ready skeleton

Paste this into the editor's Source view, then replace every [bracket] and comment. Delete Disclaimer / Safety Notes or Downloads & Assets only if they don't apply.


      


      
3.2Introduction and cover image

      
A reader decides from the first paragraph whether this tutorial solves their problem, so the introduction names the problem and the Cytron board.

      
    
        
  • MUST
    2 to 4 sentences: what the reader builds and why it matters.
    • 
        
  • SHOULD
    Open with the reader's problem, not "In this tutorial…".e.g. "Overheating equipment in server cabinets… can lead to permanent hardware damage."
    • 
        
  • MUST
    Name the Maker ESP32 and the main part, and link the Maker ESP32 at its first mention.
    • 
        
  • OPTIONAL
    A hero image or 30 to 60 s video teaser directly after the paragraph.
    • 
        
  • MUST
    Cover image: a real photo of the finished build with the Cytron board clearly visible. No stock photos. Landscape, named after the SEO URL (e.g. esp32-digital-clock.png). It shows above the page title and as the listing thumbnail.
    • 
        
  • MUST
    Blur any tokens, passwords or personal details that appear on screen.
    • 
        
  • MUST
    Check grammar and spelling (for example with Grammarly) before submitting.
    • 
      


      
3.3List of Components and product links

      
Every item Cytron sells links to its live product page, so the reader can buy the exact parts the tutorial was tested with.

      
    
        
  • MUST
    One numbered list, one line per item: [Product name] x1.e.g. "Grove to JST-SH (Qwiic) Cable - 20cm x1"
    • 
        
  • MUST
    Put the link inside the component name, and use the product name exactly as written on its product page.e.g. write "Crowtail - Temperature and Humidity Sensor 2.0", not "DHT 11".
    • 
        
  • MUST
    cytron.io links use the SEO URL only, no domain: set the protocol to <other> and paste the path./p-maker-esp32, not https://my.cytron.io/p-maker-esp32, so a reader on another Cytron store stays in their own store.
    • 
        
  • MUST
    Every link's target is New Window (_blank).Keeps the tutorial open for the reader.
    • 
        
  • MUST
    Link the Maker ESP32 at its first mention in the Introduction. Linking later mentions is allowed.
    • 
        
  • SHOULD
    A product family with several versions may link to a store search.e.g. SPG30-XX* links to a search for spg30.
    • 
        
  • MUST
    Note regional alternatives when a product differs between the stores ticked in Store Name.
    • 
        
  • MUST
    No prices, discounts or stock levels in the body text.The Hardware Components block shows live prices and stock.
    • 
        
  • MUST
    Attach every listed item in Related Product.This fills the Hardware Components block with Add to Cart.
    • 
        
  • MUST
    Items Cytron does not sell get a generic name and no link to another store.e.g. "Female-to-female jumper wires"
    • 
        
  • MUST
    No new tutorials on discontinued products. In a revamp, name the product that replaces it.e.g. NodeMCU-32S replaced by Maker ESP32.
    • 
        
  • MUST
    Open every product link, on each ticked store, before submitting.A dead product link is a lost sale.
    • 
        
  • MUST
    3D files, PCB files and downloads live on Cytron-owned storage, linked under Downloads & Assets. Never a personal Google Drive or GitHub account.
    • 
      


      
3.4Code, versions and setup

      
A reader must be able to rebuild the project months later, so tested versions are named and every file lives where Cytron controls it.

      
    
        
  • MUST
    Long code: a public GitHub Gist from the shared Cytron team account, never a personal account, so the code survives staff changes. Ask your supervisor for access.
    • 
        
  • MUST
    Short command lines: the editor's Computer Code style. Use Shift+Enter for a new line, or each line lands in its own box.
    • 
        
  • MUST
    State the IDE or toolchain version and the board package, e.g. "esp32 by Espressif Systems 3.3.12". Library versions SHOULD be named too.An unpinned core caused ledcAttach compile errors for readers on core 2.x.
    • 
        
  • SHOULD
    Open the sketch with a header comment: project, board (Cytron Maker ESP32) and main module.
    • 
        
  • MUST
    Placeholders, never real credentials: YOUR_WIFI_SSID, YOUR_WIFI_PASSWORD. Tell the reader to replace them in a Testing & Validation step.
    • 
        
  • MUST
    Code is text, never a screenshot. Terminal and Serial Monitor output can be a screen capture under Demo / Results.
    • 
        
  • SHOULD
    Name built-in libraries: when WiFi.h or WebServer.h need no install, say so in Software Setup.
    • 
        
  • MUST
    Quote error messages literally as the Troubleshooting H3.e.g. Serial Monitor shows "Failed to read from DHT sensor!"
    • 
        
  • MUST
    Proofread and test it yourself: follow your own tutorial on a clean setup before submitting. Peer review is recommended.
    • 
      


      
3.5Links, images and media

      
    
        
  • MUST
    Internal links: SEO URL only, never index.php?route=eblog/epost… URLs. Always link the Getting Started prerequisite.
    • 
        
  • MUST
    External links: official docs only, New Window (_blank). Datasheets as a PDF on static.cytron.io or a Google Docs /preview link, never /edit.
    • 
        
  • MUST
    A graphic per step: a screen capture, schematic or hardware assembly photo wherever a step needs one.A beginner follows a picture more easily than a paragraph.
    • 
        
  • MUST
    Inline images: wider than 800 px, about 300 KB (1 MB at most), clear. Set width to 800 px in Image Properties. Never upscale a smaller image; never distort the ratio.Edit in the team Canva; download as PNG limited to 300 KB.
    • 
        
  • MUST
    Diagrams and assembly photos: every connection clearly visible, labelled where needed.
    • 
        
  • MUST
    Uploading: Browse Server, then upload into the folder named after the SEO URL.
    • 
        
  • MUST
    Image file names: lowercase, hyphenated, starting with the project name.esp32-water-tank-dashboard.png, not screenshot-2025-06-04-164317.png
    • 
        
  • MUST
    Alt text on every image, screenshots included: 5 to 15 words saying what it shows.e.g. "Water tank web dashboard showing 75% level on a phone"
    • 
        
  • MUST
    YouTube: Share > Embed, tick Start at if needed, paste with the editor's Embedded YouTube Video button.

3.6Safety notes and disclaimers

      
Add the Disclaimer / Safety Notes section directly after the Introduction when any trigger below applies. Including it even for low-risk builds is good practice. Open with "This project is an educational prototype designed for learning…", then name the concrete risk and the precaution. A generic "be careful" does not count.

      

        
TriggerWhat the note must say

        
          
Mains ACOnly qualified people wire mains (relays switching 230 V, power supplies); use an enclosed, rated relay module; unplug before touching.

          
LiPo or Li-ion batteriesCorrect polarity, no short circuits, never charge unattended.

          
Motors, servos, robotsKeep fingers clear of moving parts; the code includes a stop-on-disconnect failsafe.

          
Soldering or heatVentilation and eye protection.

          
Food, pets or peopleFood-grade materials for food contact; someone checks in person if the device fails.

          
Alarms, gas, fire, temperature, medical"Educational prototype, not a certified safety device."

          
5 V sensors on 3.3 V pinsUse a level shifter or divider; state the pin voltage.

          
Passwords, bot tokens, API keysKeep them private; never publish code containing real credentials.

        
      

      
Also add warranty notes where a build could void one (modifying a board, overdriving a motor), and state that adult supervision is required when the tutorial is meant for classroom use.
